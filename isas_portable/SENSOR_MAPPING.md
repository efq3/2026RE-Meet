# 실기체 암대–IMU 라벨

사용자 지정일: 2026-11-05.

사용자 원문: “1번암대 imu1 / 2번 모터 imu 3, 3번 모터 imu2, 4번 모터 imu 4번”.

현재 4개 암대의 표시 번호에 적용하는 매핑은 다음과 같다. 기존 JSON의 CH0~CH3를 IMU1~IMU4로 대응시킨다.

| 암대 표시 번호 | IMU 번호 | 원본 JSON 채널 | 기존 온도 채널 |
|---|---|---|---|
| 1 | IMU1 | CH0 | S1 |
| 2 | IMU3 | CH2 | S2 |
| 3 | IMU2 | CH1 | S3 |
| 4 | IMU4 | CH3 | S4 |

온도 채널 대응은 기존 설정을 유지한 것이다. 이번 사용자 지정은 IMU에 관한 것으로 온도 배선을 새로 확인했다는 의미는 아니다. 동축 8개 개별 모터의 FC 출력 번호와 상·하부 매핑은 별도 실측·기록이 필요하다.

## 코드 적용

`config.json`:

```json
"imu_channels_by_arm": ["CH0", "CH2", "CH1", "CH3"]
```

- 수신 원본은 원래 CH 이름과 값으로 저장한다. 수집기에서 CH 이름을 바꿔 이중 교환하지 않는다.
- `logic.py`가 실기체 CH 패킷을 암대 순서로 변환한 뒤 RMS·상대 편차·이상 후보를 계산한다.
- 특징 로그와 웹 화면에는 암대 번호와 원본 IMU 채널을 함께 남긴다. 설정 스냅샷도 매핑을 포함한다.
- `simulation:true`로 표시된 기존 시뮬레이터와 데모는 CH0~CH3가 이미 Arm 1~4 순서로 생성된다. 이 경우 실기체 배선 교환을 적용하지 않고 실제 적용된 매핑을 특징 로그에 표시한다.
- 명시적인 `arms.arm1`~`arms.arm4` 입력은 이미 암대 라벨을 가진 데이터이므로 다시 교환하지 않는다.
- 기존 설정 파일에 매핑 항목이 없으면 종전 CH0/CH1/CH2/CH3 순서를 사용한다. 새 설정을 적용하려면 PC 서버를 재시작한다.

## 사후 분석

이 배선으로 수집한 실기체 원시 로그를 분석할 때 같은 CH→암대 대응을 사용한다. 과거 로그에도 같은 배선이 적용되었는지 확인한 뒤, 예전 'Arm 2=CH1, Arm 3=CH2' 기준 표·그림을 재생성하거나 라벨을 수정한다. 온도는 별도 대응을 유지한다. 이 파일을 추가했다고 기존 결과 그림이 자동 재생성되는 것은 아니다.
